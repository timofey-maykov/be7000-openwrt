Beam WRT 1.5.8, исправлено подключение USB extroot после сброса настроек

В фид добавлен Tailscale, после публикации пакета его можно установить командой `apk update && apk add tailscale`, в образ он не включён и включается отдельно после настройки

Мастер переноса теперь создаёт отсутствующий `fstab` до форматирования и проверяет сохранённые настройки перед сообщением об успехе, раньше UCI мог вернуть успех, ничего не записав, после перезагрузки роутер оставался на внутренней памяти

При сбросе прошивка ждёт появления USB до 15 секунд и ищет прежнюю файловую систему по UUID, смена имени `/dev/sda` больше не мешает завершению сброса, заменённый или отформатированный накопитель не очищается автоматически

На странице «Система, Накопитель» показана причина незавершённого сброса, старое задание можно отменить с сохранением копии, роутер остаётся на внутренней памяти с текущими настройками, данные на прежнем накопителе не меняются

В прошивке есть команда восстановления уже подготовленного USB extroot, она сама определяет устройство и UUID, сохраняет копии настроек и восстанавливает монтирование без форматирования

```sh
be7000-extroot-repair --reboot
```

Для предыдущих версий к релизу приложен тот же `repair-extroot.sh`, он также лежит в ZIP-архиве, скачать и запустить на роутере можно одной командой

```sh
wget -T 30 -O /tmp/repair-extroot.sh https://github.com/timofey-maykov/be7000-openwrt/releases/download/v1.5.8/repair-extroot.sh && sh /tmp/repair-extroot.sh --reboot
```

Скрипт работает с одним подготовленным ext4-накопителем с меткой `be7000_overlay`, при нескольких подходящих дисках останавливается, для выбора есть параметр `--device`, незавершённое задание сброса нужно сначала отменить

Проверены сброс, повторная попытка после сбоя, отмена задания, запись настроек настоящим UCI, интерфейс и автоопределение накопителя, отдельный скрипт восстановления подтвердил работу на BE7000 у Rootux, полный сброс с новым образом на физическом роутере пока не проверен

Beam WRT 1.5.8 fixes USB extroot setup after a factory reset.

Tailscale is available as a separate feed package. After the feed is published, install it with `apk update && apk add tailscale`, then configure it. It is not included in the firmware image.

The storage wizard creates a missing `fstab` before formatting and verifies committed settings before reporting success. Previously UCI could return success without writing any settings, leaving the router on internal storage after reboot.

Factory reset waits up to 15 seconds for USB and identifies the original filesystem by UUID. A changed `/dev/sda` name no longer prevents the reset from completing. Replaced or reformatted drives are not cleared automatically.

System, Storage shows why a reset has not finished and offers cancellation with a backup. Cancellation keeps the current settings on internal storage and leaves the previous drive unchanged.

The image includes a recovery command for an already prepared USB extroot. It detects the device and UUID, backs up settings and restores mounting without formatting.

```sh
be7000-extroot-repair --reboot
```

The same `repair-extroot.sh` is attached to this release and included in the ZIP for older firmware versions.

```sh
wget -T 30 -O /tmp/repair-extroot.sh https://github.com/timofey-maykov/be7000-openwrt/releases/download/v1.5.8/repair-extroot.sh && sh /tmp/repair-extroot.sh --reboot
```

Recovery requires one prepared ext4 drive labelled `be7000_overlay`. With multiple matching drives, it stops and accepts an explicit `--device`. An incomplete reset job must be cancelled first.

Tests cover reset and interrupted retries, cancellation, real UCI writes, the UI and automatic drive detection. Rootux confirmed the standalone recovery script on a physical BE7000. A full reset with the new firmware image has not yet been tested on physical hardware.

Beam WRT 1.5.8 修复了恢复出厂设置后 USB extroot 无法启用的问题。

软件源新增独立的 Tailscale 软件包。软件源发布后可运行 `apk update && apk add tailscale` 安装，然后单独配置。固件镜像不包含此软件包。

存储向导会在格式化之前创建缺失的 `fstab`，并在报告成功之前检查已保存的设置。以前 UCI 可能返回成功却没有写入任何设置，导致重启后仍使用内部存储。

恢复出厂设置时，固件会等待 USB 最多 15 秒，并通过 UUID 查找原文件系统。即使 `/dev/sda` 名称改变，也能继续重置。不会自动清除已更换或重新格式化的存储设备。

“系统，存储”页面显示重置未完成的原因，并可取消旧任务、保留备份。取消后继续使用内部存储和当前设置，原存储设备上的数据不会更改。

固件内置恢复命令，用于已准备好的 USB extroot。它会自动检测设备和 UUID、备份设置并恢复挂载，不会格式化。

```sh
be7000-extroot-repair --reboot
```

旧版固件可使用本次发布附件或 ZIP 中相同的 `repair-extroot.sh`。

```sh
wget -T 30 -O /tmp/repair-extroot.sh https://github.com/timofey-maykov/be7000-openwrt/releases/download/v1.5.8/repair-extroot.sh && sh /tmp/repair-extroot.sh --reboot
```

需要一个带有 `be7000_overlay` 标签、已准备好 extroot 的 ext4 存储设备。检测到多个匹配设备时会停止，可通过 `--device` 指定设备。必须先取消未完成的重置任务。

已测试重置及中断后的重试、任务取消、真实 UCI 写入、界面和设备自动检测。Rootux 已在实体 BE7000 上确认独立恢复脚本有效，尚未在实体设备上验证新固件镜像的完整重置流程。
